# 0.2.0 功能与验证范围

| 功能 | 验证方式 |
| --- | --- |
| 原版布局 | 对照 Umi-OCR 2.1.5 的标签、首屏双栏和工具按钮。应用保留五套主题。 |
| UI Automation | 通过 `InvokePattern` 导入图片、启动批量任务和关闭主窗，通过 `TextPattern` 读取和选择识别文本，通过 `ValuePattern` 编辑批量记录及二维码文本。覆盖 PDF 队列、关闭后查询 Shell 托盘和唤回同一进程。[无障碍测试记录](../verification/a11y-release.json) |
| 应用图标 | EXE 资源的 16、32、48、256 像素图标逐帧匹配原版 ICO。0.2.0 主窗经 `WM_GETICON` 返回有效图标句柄。 |
| 后台与托盘 | `--hide` 启动时只创建原生控制窗和托盘，首次显示时才创建主窗。集成版通过 Windows Shell 查询确认托盘注册。独立诊断进程模拟 `TaskbarCreated`，确认图标重新注册和退出后移除。 |
| F4 | 程序内置 Windows 低级键盘钩子。原生模块在普通用户会话中接收 Windows 注入的裸 F4，另一个前台测试窗收不到该按键，Esc 可取消选区，Alt+F4 仍关闭前台测试窗。单元测试覆盖长按去重、按下和释放配对、修饰键放行、投递失败放行。 |
| HTTP、二维码、文档 | 发布 EXE 通过图片 OCR、二维码扩展格式、文档页面和导出，以及加密 PDF 解锁流程的接口回归。[接口测试记录](../verification/http-release.json) |
| 便携 ZIP、安装 EXE | 两种包包含同一个 Windows x64 应用和推理载荷。便携 ZIP 按清单校验。安装 EXE 通过静态解包逐文件校验，安装和卸载流程未在用户电脑执行。 |

键盘模块实机验证使用 Windows 输入注入，覆盖普通用户前台测试窗。物理键盘、管理员窗口、锁屏和安全桌面、多屏混合 DPI，以及 Explorer 实际重启属于未覆盖场景。托盘图标是否在任务栏直显由 Windows 的显示设置决定。

0.2.0 每种功能页保留一个标签。原版的独立重复标签、Python/QML 插件、完整配置迁移和文档逐页范围仍有差异。批量工作流、文档类型和命令行参数见 [项目说明](../README.md)。

## 复查

从源码目录运行。下列命令使用便携目录，UI Automation 脚本用临时配置启动自己的测试实例。

```powershell
python .\tools\verify_desktop_icons.py --exe .\dist\WfZiUiBp\WfZiUiBp.exe
powershell.exe -NoProfile -MTA -File .\tools\verify_accessibility.ps1 -Executable .\dist\WfZiUiBp\WfZiUiBp.exe -Output .\verification\a11y-release.json -RequireTextEditing
```
