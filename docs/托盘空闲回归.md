# 0.2.2 托盘空闲 CPU 回归

Windows 上打开主窗口后再关闭到托盘，eframe 0.33.3 可能在等待重绘时一直轮询。隐藏窗口收不到预期的重绘事件，轮询便持续占用 UI 线程。0.2.2 在事件循环准备等待时将轮询切换为消息等待，同时保留带截止时间的重绘调度。[Windows 隐藏窗口问题](https://github.com/emilk/egui/issues/5229) · [上游事件调度修复](https://github.com/emilk/egui/pull/8398)

2026-11-06，Windows 11 x64。使用独立配置和同一套无障碍流程启动主窗、完成识别并关闭到托盘。确认原生主窗已隐藏、托盘已注册后，对进程累计 CPU 时间采样。

| 版本 | 墙钟时间 | 累计 CPU 时间 | 每秒 CPU 时间 | 回归 |
| --- | --- | --- | --- | --- |
| 0.2.1 | 5008.702 ms | 4906.25 ms | 979.545 ms | 超过上限 |
| 0.2.2 | 5007.959 ms | 0 ms | 0 ms | 通过 |

0.2.2 通过全部 30 项桌面检查，包括关闭到托盘后唤回同一进程。接口回归覆盖图片 OCR、二维码和加密 PDF。0 ms 表示在该采样窗口内未观测到 CPU 时间增长。

在源码目录运行测试。先退出正在运行的桌面实例，脚本会为测试启动独立实例。

~~~powershell
powershell.exe -NoProfile -MTA -File .\tools\verify_accessibility.ps1 -Executable .\dist\WfZiUiBp\WfZiUiBp.exe -Output .\verification\tray-idle.json -RequireTextEditing -VerifyTrayIdleCpu
~~~
