# 0.2.0 性能对照

在这台 Windows 电脑、4 线程配置和这组串行图片请求下，Rust 同权重版的热态中位延迟为 67.61 ms，比原版 105.03 ms 低 35.6%。模型保留时的工作集从 1114.61 MiB 降到 204.16 MiB，每张图累计 CPU 时间从 1018.45 ms 降到 304.36 ms。Rust v6 Tiny 的对应读数为 **39.23 ms、129.18 MiB、88.22 CPU ms/张**。

## 环境和流程

- Intel Core i9-14900HX（24 核、32 逻辑处理器），Windows 11 build 26100，平衡电源计划。三组均用 CPU，分别设 4 线程和 16 线程。
- 原版用 Umi-OCR Paddle 2.1.5 的独立临时便携副本，隐藏 Qt 主窗，启用 MKLDNN，保留推理进程以便测短期加载后闲置。进程树包含原版宿主和 PaddleOCR-json，外部 F4 工具排除。Rust 组使用同一个发布 EXE 的 HTTP 服务，ONNX Runtime 1.24.2。Rust 同权重组沿用旧检测、识别权重及字典的 ONNX 转换版。v6 Tiny 组更换检测、识别权重和字典，并使用对应预处理参数。
- 每轮启动独立进程，按 `/api/ocr/get_options` 判断就绪。闲置 2 秒后请求首张 540×160 图片。全部 8 张预热一遍，然后串行跑 6 遍。每组 3 轮，共 144 次热态请求。最后闲置 2 秒再记加载后内存。保留系统文件缓存，不把首张与启动的中位数相加当作冷启动时长。
- 图片长边上限 960，关闭方向分类、段落整理和忽略区域。客户端计时从发送已构造的本机 HTTP 请求到解析返回 JSON，包含服务器解码、推理、后处理和传输。进程的内部计时口径不同，表内统一使用客户端时间。此测试覆盖 HTTP 识别链路，F4 选区、剪贴板写入和主窗渲染耗时未计入。
- 样本为 8 张合成图，含中英混排、纯英文、中文、密排、低对比、小字噪声、倾斜和空白。每批规范化后 455 个标注字符。字符错误率按 Unicode NFKC、去除空白后的 Levenshtein 编辑距离计算。重复执行用于计时，准确率的语料量仍是 8 张。

## 结果解读

- 4 线程同权重组相比原版，模型加载后工作集减少 81.7%，每张 CPU 时间减少 70.1%，吞吐 6.56 → 9.31 张/秒。应用结构、运行时、进程通信及图像处理均有变化，差值是整条链路的结果。
- v6 Tiny 相比 4 线程同权重组，热态中位延迟减少 42.0%，加载后工作集减少 36.7%，吞吐 9.31 → 21.87 张/秒。样本字符错误率从 1.76% 降到 0.44%。桌面新配置据此默认选 v6 Tiny。日语、韩语、西里尔文以及拍照和手写识别的准确率需要独立语料。
- 线程从 4 改为 16 后，热态中位延迟为原版 105.03 → 144.19 ms，同权重 67.61 → 106.15 ms，v6 Tiny 39.23 → 59.39 ms。16 线程时，Rust 同权重组的 p99 为 551.78 ms，低于原版的 652.61 ms。默认选择 4 线程来自本机串行负载。
